# lets-encrypt-gha

Automated Let's Encrypt certificate generation via GitHub Actions with Cloudflare DNS-01 validation and multi-provider support.

## 🎯 Overview

This project automates SSL/TLS certificate generation and renewal using:
- **Let's Encrypt** as the certificate authority
- **Multiple DNS providers** for DNS-01 validation
- **GitHub Actions** for orchestration and scheduling
- **ECDSA (P-256)** for cryptographic keys (faster than RSA)

## 📁 Structure

```
├── .github/workflows/
│   └── certificate.yml      # Main pipeline
├── scripts/
│   └── generate-cert.sh     # Certificate generation script
├── output/
│   └── certs/               # Certificate files (generated by pipeline)
├── .gitignore
└── README.md
```

## 📄 Output Files

| File | Description | Usage |
|------|-------------|-------|
| `certificate.pem` | Server certificate | Web server |
| `private-key.pem` | Private key (**keep secret**) | Server configuration |
| `chain.pem` | Intermediate certificates | Chain verification |
| `fullchain.pem` | Certificate + chain (**recommended**) | Main configuration |

## 🔌 Supported DNS Providers

| Provider | Plugin | Required Environment Variables |
|----------|--------|-------------------------------|
| **Cloudflare** | `python3-certbot-dns-cloudflare` | `CF_Token`, `CF_Zone_ID` |
| **AWS Route53** | `certbot-dns-route53` | `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` |
| **Google Cloud** | `certbot-dns-google` | `GOOGLE_CREDENTIALS` (path to JSON) |
| **Azure** | `certbot-dns-azure` | `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID` |
| **DigitalOcean** | `certbot-dns-digitalocean` | `DO_API_TOKEN` |
| **Linode** | `certbot-dns-linode` | `LINODE_API_TOKEN` |
| **OVH** | `certbot-dns-ovh` | `OVH_APPLICATION_KEY`, `OVH_APPLICATION_SECRET`, `OVH_CONSUMER_KEY` |
| **RFC 2136** | `certbot-dns-rfc2136` | `RFC2136_NAMESERVER`, `RFC2136_CREDENTIALS` |

## ⚙️ Configuration

### 1. GitHub Secrets

Go to **Settings → Secrets and variables → Actions → New repository secret**:

#### Cloudflare
| Secret | Description | How to obtain |
|--------|-------------|---------------|
| `CF_API_TOKEN` | Cloudflare API Token | Cloudflare Dashboard → My Profile → API Tokens → Create Token |
| `CF_ZONE_ID` | Cloudflare Zone ID | Cloudflare Dashboard → Zone Overview → Zone ID |

**Cloudflare token permissions:**
- `Zone.Zone:Read` - Read zone information
- `Zone.DNS:Edit` - Edit DNS records (for TXT validation)

#### AWS Route53
| Secret | Description | How to obtain |
|--------|-------------|---------------|
| `AWS_ACCESS_KEY_ID` | AWS Access Key ID | AWS IAM → Users → Security credentials |
| `AWS_SECRET_ACCESS_KEY` | AWS Secret Access Key | AWS IAM → Users → Security credentials |

**IAM permissions:**
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "route53:GetChange",
        "route53:ChangeResourceRecordSets",
        "route53:ListResourceRecordSets"
      ],
      "Resource": [
        "arn:aws:route53:::hostedzone/*",
        "arn:aws:route53:::change/*"
      ]
    },
    {
      "Effect": "Allow",
      "Action": "route53:ListHostedZonesByName",
      "Resource": "*"
    }
  ]
}
```

#### Google Cloud DNS
| Secret | Description | How to obtain |
|--------|-------------|---------------|
| `GOOGLE_CREDENTIALS` | Service account JSON | Google Cloud Console → IAM → Service Accounts → Create Key |

**Permissions:**
- `dns.admin` on the Google Cloud project

#### Azure DNS
| Secret | Description | How to obtain |
|--------|-------------|---------------|
| `AZURE_CLIENT_ID` | Application ID | Azure Portal → App registrations |
| `AZURE_CLIENT_SECRET` | Client secret | Azure Portal → App registrations → Certificates & secrets |
| `AZURE_TENANT_ID` | Tenant ID | Azure Portal → Azure Active Directory |
| `AZURE_SUBSCRIPTION_ID` | Subscription ID | Azure Portal → Subscriptions |

**Permissions:**
- Contributor on the DNS Zone resource group

#### DigitalOcean
| Secret | Description | How to obtain |
|--------|-------------|---------------|
| `DO_API_TOKEN` | Personal Access Token | DigitalOcean API → Tokens → Generate New Token |

**Permissions:**
- `domain` (Read/Write)

#### Linode
| Secret | Description | How to obtain |
|--------|-------------|---------------|
| `LINODE_API_TOKEN` | Personal Access Token | Linode Manager → My Profile → API Tokens |

**Permissions:**
- Read/Write access to Domains

#### OVH
| Secret | Description | How to obtain |
|--------|-------------|---------------|
| `OVH_APPLICATION_KEY` | Application Key | OVH API → API Applications |
| `OVH_APPLICATION_SECRET` | Application Secret | OVH API → API Applications |
| `OVH_CONSUMER_KEY` | Consumer Key | OVH API → API Consumers |

**Permissions:**
- `GET /domain/zone/*`
- `PUT /domain/zone/*`
- `POST /domain/zone/*`

#### RFC 2136
| Secret | Description | How to obtain |
|--------|-------------|---------------|
| `RFC2136_NAMESERVER` | Domain nameserver | Your DNS server |
| `RFC2136_CREDENTIALS` | TSIG credentials file | Your DNS server |

### 2. GitHub Variables

Go to **Settings → Secrets and variables → Actions → Variables → New repository variable**:

| Variable | Description | Example |
|----------|-------------|---------|
| `LE_CERT_DOMAINS` | Comma-separated domains | `example.com,*.example.com,api.example.com` |
| `LE_CERTBOT_EMAIL` | Email for Let's Encrypt registration | `admin@example.com` |
| `LE_DNS_PROVIDER` | DNS provider (optional, default: cloudflare) | `cloudflare` |

## 🚀 Usage

### Via GitHub Actions (manual)

1. Go to **Actions → Generate Let's Encrypt Certificate**
2. Click **Run workflow**
3. Fill in:
   - **Domains**: `example.com,*.example.com` (comma-separated)
   - **Email**: `your@email.com`
   - **DNS Provider**: Select your provider (default: cloudflare)
4. Click **Run workflow**
5. Wait for completion and download the artifact

### Via GitHub Actions (automatic)

The pipeline runs automatically every 2 months:
```yaml
cron: "0 3 1 */2 *"  # Day 1 of every 2nd month at 03:00 UTC
```

### Local (development/testing)

```bash
# Install dependencies (Ubuntu/Debian)
sudo apt-get update
sudo apt-get install -y certbot python3-pip

# Install provider plugin (example: Cloudflare)
pip3 install certbot-dns-cloudflare

# Set environment variables
export DOMAINS="example.com,*.example.com"
export CERTBOT_EMAIL="admin@example.com"
export DNS_PROVIDER="cloudflare"
export CF_Token="your-token-here"
export CF_Zone_ID="your-zone-id-here"

# Run script
chmod +x scripts/generate-cert.sh
./scripts/generate-cert.sh
```

Files will be generated in `output/certs/`.

## 🔒 Security

- ✅ Private keys are stored in GitHub Actions artifacts (90-day retention)
- ✅ `.gitignore` excludes `.pem` files from local commits
- ✅ Workflow commits only certificates (via automated bot)
- ✅ Never expose `private-key.pem`
- ✅ Use environment variables or GitHub Secrets for credentials

## 🔄 Renewal

- **Frequency**: Every 60 days (certificates are valid for 90 days)
- **Schedule**: Day 1 of every 2nd month at 03:00 UTC
- **Automatic**: Workflow commits new certificates
- **Manual**: Run the workflow whenever needed

## 🛠️ Customization

### Add new domains

Edit the `LE_CERT_DOMAINS` variable in GitHub:
```
example.com,*.example.com,api.example.com,app.example.com
```

### Change key type

To use RSA instead of ECDSA, edit `scripts/generate-cert.sh`:
```bash
# Change from:
--key-type ecdsa \
--elliptic-curve secp256r1 \

# To:
--key-type rsa \
--rsa-key-size 4096 \
```

### Change schedule

Edit the cron in `.github/workflows/certificate.yml`:
```yaml
schedule:
  # Example: every day 1st of month at 03:00 UTC
  cron: "0 3 1 * *"
```

### Change DNS provider

Edit the `LE_DNS_PROVIDER` variable in GitHub or select in manual workflow.

## 🐛 Troubleshooting

### Error: "DNS problem: NXDOMAIN looking up TXT"

- Verify the provider token has permission to edit DNS records
- Wait for DNS propagation (may take up to 5 minutes)

### Error: "Too many certificates already issued"

- Let's Encrypt has a limit of 50 certificates per domain per week
- Wait 7 days or use a different domain for testing

### Error: "Unauthorized"

- Verify provider credentials are correct
- Confirm permissions are properly configured

### Error: "Plugin not installed"

- The provider plugin is not installed
- Run: `pip3 install certbot-dns-<provider>`
